## Findings

### R1 — Required: native admission misclassifies inconsistent provider output

**Severity:** medium. **Disposition:** blocks approval of this M03 handoff.  
**Location:** [ckdpub-composition-probe.php](ckdpub-composition-probe.php),
`NativePointTrial::admit()`, lines 149–158; propagation through
`parsePublicNode()`, lines 178–185.  
**Affected obligations:** M02 O06; M03 Q12; CP-07 and CP-10.

After successful native parsing, `admit()` serializes the returned object and
checks exact byte equality with the input. If the bytes differ, it throws
`TrialFailure('malformed_point')`. `parsePublicNode()` preserves that category.
For an already valid, canonical input this is an observable provider-output
inconsistency, not evidence that the request was malformed.

The equivalent PHP adapter mismatch branches use `provider_failure`, and
[qualifiedNativeTweak()](native-false-classifier.php) also correctly treats a
successful parse followed by unequal serialization as `provider_failure`.
The native admission path therefore disagrees with both the intended meaning
and the other implementations. The README's discussion of the classifier
does not make the separate `NativePointTrial::admit()` branch correct.

**Independent counterexample, reproduced on PHP 8.3.35 and 8.4.26:**

1. Use the valid parent payload from `vector_2_root_to_0`.
2. Preserve the actual native parse of its public key.
3. In a disposable copy of the research adapter, replace only the serialization
   result in `NativePointTrial::admit()` with the compressed generator `G`.
   This models a wrong, well-formed serializer result after a successful parse.
4. Call `parsePublicNode($payload, new NativePointTrial())`.
5. Observe `malformed_point`; the required category is `provider_failure`.

This is a **controlled injected fault**, not behavior observed from the real
pinned serializer. Unlike an identical off-curve signal or coordinated lying
providers, this fault is distinguishable locally: the equality check already
detects it. The adapter assigns the wrong meaning to that detection. Although
the operation stops and emits no child, deterministic failure semantics are
part of the accepted boundary and of the M03 fault-classification claim.

**Required correction:** classify serialization mismatch as provider failure
in the native admission adapter and add a focused challenge at that actual
lower boundary. Keep genuine native parse rejection of a malformed point as
`malformed_point`. Test a different finite point, malformed serialized output,
and a serialization exception after successful parsing; ensure none becomes
an input error or a successful child. Rerun the native composition and affected
comparison on both runtimes, and update the evidence/claim as needed. This
does not require selecting a backend or creating a production API.

**Reproduction without changing repository files:** prepare the locked M03
dependencies at `/research`, mount M03 at `/probe`, and load the matching native
extension as described in the executor's reproduction instructions. Run the
following PHP script from a scratch mount. It extracts the declarations before
the command-line harness and injects only the indicated native serialization
result:

```php
<?php
declare(strict_types=1);
$source = file_get_contents('/probe/ckdpub-composition-probe.php');
$prefix = explode("\n\$selected =", $source, 2)[0];
$prefix = str_replace(
    "__DIR__ . '/native-false-classifier.php'",
    "'/probe/native-false-classifier.php'",
    $prefix

$needle = '$canonical = secp256k1_ec_pubkey_serialize($parsed);';
if (substr_count($prefix, $needle) !== 1) {
    throw new RuntimeException('Reviewed injection site changed');

$prefix = str_replace($needle, $needle .
    '$canonical = hex2bin("0279be667ef9dcbbac55a06295ce870b07029bfcdb2dce28d959f2815b16f81798");',
    $prefix);
eval(substr($prefix, 5));
$fixtures = json_decode(file_get_contents('/probe/ckdpub-public-fixtures.json'), true);
$payload = hex2bin($fixtures['official_vectors']['vector_2_root_to_0']['parent']);
```

### R2 — Downstream requirement: CKDpub exceptions retain raw diagnostic chains

**Severity:** medium before public exposure; nonblocking for internal research.  
**Locations:** `TrialFailure::__construct()` and the HMAC/ECC catches in
[ckdpub-composition-probe.php](ckdpub-composition-probe.php), lines 20–25,
217–233; exception wrapping in [native-false-classifier.php](native-false-classifier.php).

The hash/conversion probe explicitly drops the original exception and checks
that `getPrevious()` is null. The CKDpub probe instead retains the original
throwable. Injecting `LogicException('review-only vendor diagnostic marker')`
through the HMAC callback produces `TrialFailure('provider_failure')` whose
`getPrevious()` exposes that class and message. This reproduced with all three
adapters on both runtimes. Existing category-only checks still pass.

That is not a current public API leak: these are internal research helpers,
and no production address operation exists. It does mean the hash wrapper's
safe-diagnostic result cannot be generalized to the CKDpub composition. Before
M05/M06 public use, establish one public sanitization boundary and test the
observable exception chain, message and context with deliberately sensitive
synthetic diagnostics. Internal causes may be retained only where they cannot
escape that boundary. Do not copy `TrialFailure` as a qualified public exception
implementation. No production secrets were used in this review.

### R3 — Improve the HASH160 negative control

**Severity:** low; nonblocking.  
**Location:** [hash-conversion-probe.php](hash-conversion-probe.php), line 151.

The assertion labelled `HASH160 order` compares
`SHA256(RIPEMD160(key))` with `SHA256(key)`, not with the actual `HASH160`
result. It therefore does not itself test the order of the composition whose
result is being qualified. This is not evidence that current HASH160 is wrong:
the preceding 20-byte width and published BIP32 fingerprint checks pass and
would reject the simple reversed composition. Complete-node CKDpub comparisons
also check the parent fingerprint.

Use a negative control that deliberately substitutes the wrong composition
and proves that the same known-answer assertion rejects it, preferably with a
sourced full 20-byte HASH160 answer when M04 qualifies address construction.
The current four-byte fingerprint is a useful bounded anchor, not a published
answer for every byte of the 20-byte digest. The empty HMAC case is correctly
labelled an observation rather than a sourced known answer.
