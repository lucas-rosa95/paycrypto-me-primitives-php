## Changes and finding dispositions

### R1 — Closed

`NativePointTrial::admit()` now reserves `malformed_point` for rejected point shape or an actual native parse rejection. After successful parsing, a different point, wrong-width output, non-string output or serialization exception becomes `provider_failure`. Parse exceptions are also normalized to provider failure. Exact byte equality remains required before admission succeeds.

The serializer override is an optional research fault-injection hook. Normal execution still invokes the real native serializer; native parsing remains real in the focused fault mode. No fallback or public API is introduced. The corrected behavior agrees with the PHP adapters' failure meaning and the existing native tweak helper.

The new `--native-admission-faults` mode proves that a valid published parent is admitted, the BIP32 vector 5 off-curve input remains malformed, and four serializer faults become provider failures. The off-curve test prevents serialization after rejected parsing. Both saved runtime records reproduced exactly.

The reviewer additionally tested long serialization, a 33-byte result with an invalid prefix, a 33-byte off-curve result, and `null`. All became `provider_failure` on both runtimes. A hook forwarding to the real serializer admitted the valid parent; a counter confirmed zero serializer calls for the rejected off-curve input.

To check that the new regression detects the original defect, a disposable copy restored only the native mismatch branch's former `malformed_point` category. The new fault mode failed on both runtimes with:

```text
wrong_finite_point: expected provider_failure, got malformed_point
```

The repository source was not mutated. This negative control demonstrates that the test rejects the original semantic error rather than merely producing a new success record.

### R2 — Retained downstream, not a merge blocker

The executor now explicitly records that internal `TrialFailure` chains can retain raw vendor diagnostics and that the isolated hash wrapper's sanitization test does not qualify CKDpub diagnostics. The execution plan preserves the M05/M06 requirement to define and test public message, context and exception-chain sanitization.

That is the disposition required by the earlier review for this internal research scope. No public address operation exists in this increment, and no new claim of public diagnostic containment was introduced. R2 must still be resolved before public exposure.

### R3 — Closed for the requested negative-control improvement

The hash probe now compares both the correct composition and the deliberately reversed composition against the published BIP32 fingerprint. The correct value is `bd16bee5`; the reversed value is `13ce5fe1` and is rejected by that same expected fingerprint. Both updated JSON records reproduced exactly.

This corrects the prior comparison against an unrelated intermediate SHA-256 value. It remains a four-byte fingerprint anchor. The executor appropriately leaves a sourced full 20-byte HASH160 answer and address integration to M04.
