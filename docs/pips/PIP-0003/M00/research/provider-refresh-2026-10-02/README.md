## Provenance

- WooCommerce reference checkout: `777559de23002d84ad243be50de243df9690bbf1`, clean
  at inspection. All mounts were read-only; WordPress and the database were not
  started. The reference vendor is available on the host.
- [Installed reference packages](installed-reference-packages.json) record the
  lock identities. BitWasp Bitcoin 1.1.0 still uses installed Paragonie 2.5.0;
  the new ECC probe loads separately downloaded Paragonie 2.6.0 source.
- [Package metadata](package-metadata.json) is a field-preserving extraction of
  each named package's first stable entry from
  `https://repo.packagist.org/p2/<vendor>/<package>.json` on the checkpoint date.
  No production dependency lock was generated by this research.
- [Advisories](advisories.json) preserve the public response from
  `https://packagist.org/api/security-advisories/` with `packages[]` for
  paragonie/ecc, simplito/elliptic-php, bitwasp/bitcoin, bitwasp/bech32,
  tuupola/base58 and stephenhill/base58. This query is not a full dependency audit.
- [Binding metadata](native-binding-metadata.json) preserves the relevant fields
  of `https://api.github.com/repos/Bit-Wasp/secp256k1-php`. Native code was not run.
- [BIP173](bip-0173.mediawiki) is from
  [BIPs revision 3a10b5b5](https://github.com/bitcoin/bips/blob/3a10b5b5f0a7586df8928d580a3009744ebb2079/bip-0173.mediawiki);
  [revision metadata](bips-revision.json) identifies that source. Valid v1+
  examples are deliberately excluded; the probe covers all seven generic valid,
  twelve generic invalid, three valid v0 and ten invalid SegWit entries.
- BIP32 public strings come from the existing
  [snapshot](../../reviews/bitwasp-public-derivation/bip-0032.mediawiki).
- Hash known answers: SHA-256 `abc`, the design authors'
  [RIPEMD-160 empty-string vector](https://homes.esat.kuleuven.be/~bosselae/ripemd160.html) and
  [RFC 4231 case 1](https://www.rfc-editor.org/rfc/rfc4231#section-4.2).
  The P2PKH example is the published
  [Base58Check example](https://en.bitcoin.it/wiki/Technical_background_of_version_1_Bitcoin_addresses).
  The four StephenHill binary cases are local comparison cases, not normative
  vectors. ECC generator/order values are public curve parameters; no private
  key is generated or used.

## Reproduction

The issued `SHA256SUMS` identifies the original pack at Git revision `55b4a7b`.
This README was revised after that assessment and its paths updated again when
the pack moved. From this directory, verify the unchanged
stored data and scripts with `sed '/  README.md$/d' SHA256SUMS | sha256sum -c`.
Download external source into a fresh scratch directory, leaving repository dependencies
unchanged:

```bash
bash fetch-candidates.sh /tmp/primitives-provider-refresh
(cd /tmp/primitives-provider-refresh && sha256sum -c /absolute/path/to/this/directory/ARCHIVE-SHA256SUMS)
```

`ARCHIVE-SHA256SUMS` records the downloaded archive bytes. If GitHub repacks an
archive, inspect its source identity before comparing outcomes; do not silently
accept a hash mismatch. Source commits and the fetch script provide recovery
references. External source code is not copied into Primitives production code.

Set absolute paths and a recorded image available on your machine:

```bash
research_root=/absolute/path/to/paycrypto-me-primitives-php/docs/pips/PIP-0003/M00/research/provider-refresh-2026-10-02
old_evidence=/absolute/path/to/paycrypto-me-primitives-php/docs/pips/PIP-0003/M00/reviews/bitwasp-public-derivation
reference_root=/absolute/path/to/paycrypto-me-for-woocommerce/src/trunk
candidate_root=/tmp/primitives-provider-refresh
research_image=sha256:67a488dd95f2067bb10406e48afb34dbd01f728ec0fca4eabffda736f1467b31

docker run --rm --network none --read-only \
  --mount "type=bind,src=$candidate_root,dst=/candidates,readonly" \
  --mount "type=bind,src=$reference_root,dst=/reference,readonly" \
  --mount "type=bind,src=$research_root,dst=/evidence,readonly" \
  --mount "type=bind,src=$old_evidence,dst=/old-evidence,readonly" \
  --entrypoint php "$research_image" /evidence/probe.php > /tmp/provider-probe.json
cmp "$research_root/probe-php83.json" /tmp/provider-probe.json
```

Repeat with the recorded 8.1 image and `probe-php81.json`. An image ID identifies
the local run, not a distributable or independently reproducible image build.
On another environment, record its identity and compare semantic outcomes without
overwriting these observations.
